The Three Tools

StringFlow Translate

Fills in empty cells in a String Table Collection using a local machine-translation server. It never touches a cell that already has a value, so running it is always non-destructive — on a fresh table or one you've been hand-editing for months.

Open it from Tools ▸ StringFlow ▸ StringFlow Translate. It needs a running translation server — see StringFlow Environment Setup if you haven't set one up yet.

Checking the connection

Press Test All. The status line reads All N connected once every enabled backend answers. If it doesn't, StringFlow Environment Setup is where that gets fixed — this window only tests and uses backends, it doesn't install or start them.

Running a translation

FieldWhat it does
TableThe String Table Collection to translate.
Source Language The locale to translate from. Auto picks the first non-empty value per key — useful for a table filled in unevenly across locales.
Target Language Auto / All Empty fills every other locale's empty cells in one run, not just one target at a time.
Translation Type All Missing considers every key in the table; Selected Missing considers only the keys you've checked in the key list below.

Press Translate.

Both modes only fill empty cells

Neither Translation Type can overwrite an existing value — machine or human, reviewed or not. There is deliberately no "this will replace N entries" confirmation, because there's nothing to replace. Re-running the exact same settings twice in a row is a no-op the second time. To force a specific cell to be re-translated, clear it first with StringFlow Tables' Clear Values.

Reading the key list

Below the run settings, the key list shows every key in the selected table — in the same order Unity's own Table window shows them — with a search field to filter by name. In Selected Missing mode, checkboxes appear alongside Select All (checks every currently visible/filtered key) and Select None.

Each key's row shows one colored dot per locale. The color reflects the latest recorded translation outcome for that exact cell — not just whether it currently has a value, which is a meaningfully different question a plain text-filled/empty view can't answer:

Dot meaningWhat it tells you
Empty, never triedNo value, and no run has ever attempted this cell.
Empty, skippedA run deliberately skipped this cell (e.g. source and target were the same locale for it) and it's still empty.
Empty, failedA run tried this cell and it failed — still empty, but not for lack of trying. Worth investigating rather than assuming it'll fix itself on the next run.
Filled, no recorded runHas a value, but nothing in history explains where it came from — pre-existing text, or something typed in by hand.
Filled, cleanHas a value from a run that translated the whole string in one clean pass.
Filled, needs reviewHas a value, but it came from a run that had to fall back to translating in segments — worth a human glance.

Hover any dot for the exact detail behind it, including which run produced it, via StringFlow History.

What's protected from translation

Before a string is sent to the server, StringFlow strips off any Rich Text tag that wraps the entire string (e.g. a leading <color=red> and its matching trailing </color>) and sends only the text between them — those tags never touch the translator and come back exactly as they were.

Everything else that shouldn't be translated — placeholders like {playerName}, {0}, printf-style %s / %d, inline Rich Text tags in the middle of a sentence, and emoji — is swapped for an index token before sending, and swapped back afterward. This is why Hello {playerName}, you have %d coins left comes back with {playerName} and %d intact instead of translated or mangled. A cell built this way is what shows as Filled, needs review in the key list above — the meaning is normally right, but it's worth a native speaker's eye since it was reassembled from segments rather than translated as one clean sentence.

Progress, Cancel, and "nothing to translate"

Tick Show Progress to watch a run work key by key. Cancel stops it at any point — whatever finished up to that point is kept, nothing is rolled back. Press Refresh afterward to re-read the table's current state.

If you press Translate and every applicable cell in scope is already filled, a dialog says so plainly — "Nothing to translate — all applicable cells are already filled." — rather than silently doing nothing. If you were expecting it to fill something, check Translation Type (are the right keys actually selected, for Selected Missing?) and Source/Target Language before assuming something's broken.

Performance settings

A collapsible Performance section controls how a run is dispatched — never what anything is translated to, and it applies across every backend a run might use, not just one:

  • Parallel Requests — how many requests may be in flight at once. Defaults to your machine's logical core count. Translation backends are typically CPU/GPU-bound, so raising this past what a backend can actually chew through won't speed anything up and can cause timeouts instead.
  • Entries per Request — how many entries of the same language pair share one HTTP request. Each is still translated completely independently by the backend — nothing is merged, nothing is split, results are identical to one-request-per-entry, just with less network overhead. Set to 1 to reproduce the original one-entry-per-request behavior exactly.
  • Identical source text within one run is translated once and the result reused across every key that shares it — nothing is cached between separate runs, though.

Underneath, a request timeout toggle:

  • Unlimited (default) — a request waits exactly as long as it takes, with no automatic recovery from a genuinely stuck one.
  • Limited — a request that hasn't answered within the configured time is treated as failed, retried, then falls back to the next backend, exactly like any other network error. This is what protects a run from a dropped connection or a crashed container hanging forever.

⚠ A GPU backend's first request is legitimately slow

A local GPU-backed engine can take far longer on its very first request than every one after it — the model is warming up CUDA kernels, not stuck. A Limited timeout tuned for steady-state can kill that one legitimate slow call before it finishes; there's a specific "ignore for first entry" option alongside the timeout for exactly this case. If a run's very first translation always fails but everything after it works, this is almost certainly why.

StringFlow Routing

Press Configure Routing… to open it. This is where backends, language maps, and routing preferences live.

Backends

Each row: a checkbox to enable/disable it for the router, its URL (editable, commits on Enter or losing focus), a Test button, and reorder/remove controls. Add Backend creates a new disabled entry pointed at a placeholder URL — see Connecting Custom Backends for wiring up your own server.

Priority order and Rules

For any (source, target) pair with no more specific instruction, StringFlow walks the backend list top to bottom — this is the same reorderable list shown in both windows. Rules override that for specific pairs: an ordered list of source → target → backend, either side allowed to be * for "anything." The first enabled rule that matches wins that pair's preferred backend — still just a preference, since if that backend can't actually serve the pair, the fallback order still applies underneath it.

Dynamic Routing

When on, the backend that most recently actually succeeded for an exact (source, target) pair is remembered and preferred next time, with no rule needed — routing gets faster to converge the more you translate. An explicit Rule always wins over a learned shortcut. When off, routing is fully static: only Rules and the fallback order decide anything.

Language code maps

Only needed for a backend whose language codes aren't Unity locale codes already (LibreTranslate is discovered live and needs no map at all). Add a Unity locale code on one side and that backend's own code for it on the other. A locale with no entry is simply skipped on that backend, never a hard failure — see Connecting Custom Backends for the full picture.

StringFlow Languages

Open it from the Language Support… button. A read-only, searchable list of every language each configured backend can currently be asked to handle.

⚠ LibreTranslate's languages only appear after you Test it

This window makes no network calls of its own — it only reads what's already known. LibreTranslate's language list specifically comes from its last live Test this session. If StringFlow Languages shows LibreTranslate covering zero languages, that doesn't mean the server has no languages — it means it hasn't been tested yet this session. Go test it in the main window (or press Test All) and this list updates.

Every other backend's languages come from its static language-code map on StringFlow Routing instead, which needs no live test to read.

StringFlow History

Press History to open it — a genuine chronological record of every translation run, grouped by run ("Translation 1", "Translation 2", …), each collapsible.

  • Table — pick one table's history, or All Tables for every recorded run across the project.
  • Filter — All / Translated / Needs Review / Failed / Skipped.
  • Search — filter by key name.
  • Each row shows a Source cell (that key's actually-resolved source locale and text) followed by one cell per target locale that run wrote, colored to match the same clean/needs-review/failed/skipped states as the key list's dots.

Clicking a row that still resolves to a real key opens it directly in Unity's native Table window. A key or table that's since been deleted is marked (deleted) rather than silently vanishing from history or crashing the window — the record survives even though there's nothing left to jump to. Right-click a run or a single entry to delete just that record; the toolbar's Delete All clears everything currently shown.

Deleting history is always safe

Deleting a history record — one entry, one run, or everything via Delete All — only ever removes the record of what happened. It never touches the table itself or any translated text currently sitting in it.
