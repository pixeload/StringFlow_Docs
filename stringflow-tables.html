The Three Tools

StringFlow Tables

Finds text sitting in your scenes and prefabs that isn't going through Unity's Localization system yet, links it to a String Table, and keeps your tables clean as the project grows. Needs no server, no Docker, and no network — it only reads and writes your project's own assets.

Open it from Tools ▸ StringFlow ▸ StringFlow Tables.

Scanning your project

Choose a scope from the dropdown on the left of the toolbar, then press Scan.

ScopeWhat it covers
Current SceneOnly the scene open right now. The fastest option, good for iterating on one screen.
Selected SceneA scene you pick, without opening it.
Selected PrefabsWhatever prefab assets you have selected in the Project window.
All ScenesEvery scene asset in the project, whether or not it's in Build Settings.
Build Settings ScenesOnly the scenes actually included in your build.
Entire ProjectEvery scene and every prefab. The most thorough option — and the slowest on a large project.

The scan looks for text-bearing components — TextMeshPro (TMP) and Unity UI's legacy Text — on every GameObject in scope, whether or not they already have a Localize String Event (LSE) component attached. A progress bar with its own Cancel appears for anything large enough to take a moment; whatever finished scanning before you cancel is kept.

Scan vs. Refresh — the distinction that matters most

The toolbar has two buttons that look similar and behave differently. Getting this backwards is the single most common cause of "I made a change and nothing here reflects it":

ButtonWhat it actually does
Scan Scans using the current mode, but reuses cached results for anything unchanged since the last scan — fast, but it can miss a change that happened outside this window (in another Unity tool, a script, or by hand-editing a table) if that change didn't touch the objects StringFlow Tables is tracking.
Refresh Re-scans everything from scratch, ignoring the cache entirely. Slower, but guaranteed current. Use this whenever you're not sure the list in front of you reflects reality — right after using StringFlow Translate, StringFlow Tables' own auxiliary windows, or Unity's native Localization Tables window.

⚠ If something looks stale

Press Refresh, not Scan — that's the button that actually discards cached state. If a window is still showing old data after that, closing and reopening it forces a completely fresh read as well, which covers the rare case of a window's own in-memory state (not just the scan cache) having drifted from the project.

Filtering and selecting results

The status filter column on the left doubles as a live count and a toggle:

  • All — every scanned text object.
  • Localized — bound, resolves to a real table and key, and is wired to update its text.
  • Unlocalized — no localization binding at all yet.
  • Broken — the referenced table doesn't resolve (deleted or renamed collection), or the reference itself is invalid.
  • Missing Key — the table resolves, but the key it references doesn't exist in it.
  • Empty — an LSE is present but its reference is empty.

Above the results list, a free-text search filters by GameObject name and current text, and a selection toolbar operates on whatever the filter/search currently shows:

  • Select All — every row matching the current filter and search.
  • Deselect All — clears the selection.
  • Invert — swaps selected and unselected, within the current filter/search.

If any objects are Unlocalized, an Auto Bind All (N) button appears next to the filters — it selects every one of them in one click and opens the Bind panel immediately, skipping the manual select-then-click-Bind step for the common case of "just localize everything unlocalized."

Reading a result row

Each row shows, left to right: a status icon, the scene or prefab it lives in, the GameObject's name, a component badge (TMP or Text), a truncated preview of its current on-screen text, and — once bound — its resolved Table/Key.

Every status, in full

The filter dropdown covers the six you'll see day to day, but the scanner actually tracks eight distinct outcomes internally. The extra two don't have their own filter bucket — they only show up under All — but they're worth knowing about, because they represent a real, specific problem each:

StatusMeaning
LocalizedBound, resolves to a real table and key, and is actively wired to update a recognized text component. Nothing to do.
UnlocalizedA recognized text component with no localization binding at all yet.
Broken BindingThe table this binding points at no longer exists — deleted or renamed collection. Shown under the Broken filter.
Invalid ReferenceThe reference itself is malformed in a way that isn't specifically a missing table or key. Also shown under Broken.
Missing KeyThe table resolves fine, but the specific key it references doesn't exist in it any more — usually a key renamed or deleted directly in the Table window.
Empty BindingAn LSE component exists, but its table/key reference is empty — never actually pointed anywhere.
Disconnected (no dedicated filter) The binding is completely valid — real table, real key — but the LSE's own update event has zero listeners. It resolves cleanly and will never be flagged as broken, but it also isn't wired to update anything's text on screen. Easy to miss because it looks fine at a glance; only visible under All.
Needs Review (no dedicated filter) Valid binding with at least one listener, but none of them are a TMP_Text or legacy Text component the scanner can verify — it's wired to something, just not something this tool can confirm is a text display. Worth a manual look. Only visible under All.

In practice: if a count in All is higher than Localized + Unlocalized + Broken + Missing Key + Empty added together, the difference is Disconnected and/or Needs Review rows — switch to All and look at each row's status text (hover the icon) to find them.

The Details panel

Selecting one or more rows populates the Details panel below the list. With a single row selected, it shows the GameObject name, its scene/prefab location, its full hierarchy path, its component type, its current text, its full status (including the specific detail message for anything not cleanly Localized), and — once bound — its table, key, and how many other objects in the current scan reference that same table/key. With multiple rows selected, it instead shows a one-line breakdown (localized / unlocalized / broken counts) and batch versions of the same action buttons.

There's deliberately no "pick any key for this one object" button anywhere in this tool — that's exactly what the Inspector's own LocalizedString field picker already does, and duplicating it here would just be a second way to do the same thing.

Binding text to a key

Available for Unlocalized rows, as Bind (single row) or Batch Bind (N) (multi-select). Set:

  • Source Locale — the language the object's current on-screen text is written in; its value is written into the new key under this locale.
  • Target Table — which String Table Collection the key is created in (or looked up from, if a matching one already exists).
  • Key Mode — Share Key for Matching Text gives every selected object with identical current text one shared key (fewer keys, but two objects that happen to say the same thing right now will always update together afterward), or Unique Key per Object gives every object its own key regardless of matching text — the safer default when several objects share default placeholder text (several buttons all saying "Button", for instance) that shouldn't be tied together.

Press Preview… to open the shared Preview / Apply window before anything is written.

Change Table

Available for already-bound rows. Moves the selected objects' keys to a different String Table Collection, copying every locale's existing value across automatically. Pick the Destination Table, then Preview… the move before applying it.

Unbind

Removes the localization component from selected bound objects. The object's current on-screen text is preserved exactly as-is — unbinding never blanks anything, it just stops that object being driven by a table. Batch unbinding shows one confirmation regardless of how many objects are involved, and is undoable via Ctrl+Z.

Prefab instances and overrides

Selecting a prefab instance whose localization binding has been overridden away from its prefab source shows a dedicated notice with two choices:

  • Match Prefab Binding — discards this instance's override so it goes back to matching the prefab. Never modifies the prefab asset itself. Not undoable via Ctrl+Z.
  • Keep Scene Override — leaves the instance exactly as it is; simply dismisses the notice for now (it reappears the next time you select this row, since the override genuinely still exists — nothing is silently remembered as "already handled").

Automatic repair suggestions

Selecting a row with a broken-like status (Broken Binding, Missing Key, or Invalid Reference) shows a Repair section underneath, offering whichever of these three automatic fixes actually apply — highest confidence first:

  1. Use "Table/Key" (same text) Another object elsewhere in the current scan already localizes the exact same current text under a real key. This is the highest-confidence fix available, since it means the correct key almost certainly already exists — it just repoints this object at it.
  2. Use "Key" (closest key name, N edits) Shown only when the broken reference is by name and a very similarly-named key exists in the same table (within 3 character edits) — the classic signature of a key that was renamed or typo'd. The suggestion names the exact edit distance so you can judge for yourself whether it's really the same key.
  3. Create Missing Key Here Only for Missing Key rows: creates the exact key this binding was already pointing at, in its current table, left empty. Fill it in afterward via Unity's Table window or StringFlow Translate.

If none of these apply, the panel says so plainly and points you at fixing the binding directly in the Inspector, or using Unbind — there's no generic "pick a key" escape hatch here either, for the same reason as above.

Selecting multiple broken-like rows at once shows a single Repair (N) button instead, which builds one combined preview covering the best fix for every row in the selection.

The Preview / Apply window

Bind, Change Table, and Repair all funnel through the same preview window rather than each having its own dialog. It always shows a summary line first — total objects, unique strings, existing-key matches, new keys required — followed by one row per unique string or binding, where you can adjust the outcome before anything is written:

  • Use Existing — reuse a key that already holds this exact text (only offered when one exists).
  • Create New / New Key — make a new key, editable inline before applying.
  • Skip — leave this particular row untouched (offered for Change Table and Repair; not for a plain Bind, where every row is new by definition).

Nothing is written until you press Apply — Cancel, or simply closing the window, leaves everything exactly as it was. One confirmation dialog covers the whole batch, however many objects are involved.

⚠ Prefab asset writes are the one exception to Undo

If the preview includes any object that lives directly on a prefab asset (not a scene instance of one), the window warns you before you apply: those specific writes are not undoable via Ctrl+Z. Everything else this tool does — Bind, Unbind, Change Table, Merge Keys, Delete Unused Keys, Clear Values — is undoable normally; this is the one genuine exception, and the tool always tells you when it applies before you can apply anything.

Coverage

Press Coverage… in the Keys toolbar to open Localization Coverage — a visual audit, not a wall of numbers.

  • Overall — a pie chart plus a legend of Localized / Unlocalized / Needs Attention (this bucket combines Missing Key, Broken Binding, Empty Binding, Disconnected, and Needs Review into one "something's off here" figure — switch to the main window's filters, or the All filter, to see exactly which).
  • By Scene / Prefab — the same three-way breakdown, one horizontal bar per scanned location, so you can see exactly where the unlocalized text physically lives.
  • By Table — a different question, since a table has no notion of "unlocalized" on its own: how many keys exist, how many are actually referenced by anything the last scan found (used vs. unused), with a ⚠ badge on any table that also has duplicate source text or references to a key that no longer exists in it.

Coverage computes from whatever the main window's last scan found — its own Refresh button recomputes from those same results, it doesn't run a new scan itself. If you haven't scanned yet, it says so and asks you to scan Entire Project first for the most complete picture.

Find Duplicate Text

Open it from the Keys toolbar. Finds every group of keys — across every table in the project, not just one — that currently hold identical text in a chosen Compare Locale. Two keys with the same source text are two separate translation jobs that can silently drift apart over time; this is how you find and consolidate them.

  1. Each group starts collapsed; expand one to see every table/key holding that text, all checked by default.
  2. Uncheck any entry you want left alone — only checked entries are considered for the merge.
  3. With 2+ still checked, pick which one Keeps — it keeps its name and receives the combined values; the others are deleted.
  4. Press Merge N Selected… to build a preview.

The preview shows exactly which keys will be removed, how many objects will be automatically repointed to the survivor, and — critically — flags any locale where the checked keys currently hold different values (a real conflict, not just a duplicate). For each conflicting locale you pick which value survives via a toolbar. Locales with no conflict combine automatically. Press Merge Keys to apply — one confirmation regardless of size, and this one is undoable via Ctrl+Z (no prefab-asset caveat here, since it only ever touches table data).

Find Unused Keys

Open it from the Keys toolbar, pick a table. Lists every key with zero references in the main window's last scan — this window doesn't run its own scan, it reads whatever the main window already found. If nothing has been scanned yet, it says so up front rather than showing a misleadingly empty list.

⚠ Before deleting

"Unused" means "not referenced by the scan currently in memory." A key used only by a scene or prefab outside that scan's scope will show as unused even though it's genuinely in use — and a key assigned dynamically in code is invisible to any static scan regardless of scope. Run Entire Project in the main window first if you want this list to be trustworthy, and double-check before deleting either way.

Select All / Deselect All / Invert work the same way as everywhere else in this tool. Delete Selected (N) shows one confirmation and is undoable via Ctrl+Z.

Clear Values

Open it from the Keys toolbar, or from a row's Details panel with objects already selected. Bulk-clears the text value for a set of keys, in one locale or every locale at once — genuinely new functionality Unity's own Table window has no equivalent for.

  • From Selection — uses the keys resolved from whatever's currently selected in the main window (only offered when that selection actually has bound rows).
  • Pick Table & Keys — choose a table and any of its keys directly, whether or not they're currently bound to anything in a scan.

Then choose Clear In: a specific locale, or All Locales to wipe every locale's value for the selected keys at once. The preview line does the multiplication for you — N keys × M locales = however many individual values will actually be cleared. Press Clear Values; one confirmation, undoable via Ctrl+Z.

The deliberate use case

Clear Values is how you force a specific cell to be re-translated: clear it here, then run StringFlow Translate, which — by design — only ever fills cells that are currently empty. Clearing is the intentional way to make room for a fresh pass on specific entries without touching anything else in the table.
