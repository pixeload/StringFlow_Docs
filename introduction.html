StringFlow Documentation

Localization for Unity, without leaving the Editor

StringFlow is three tools that share one job: get every string in your project into Unity's Localization Tables, and get every table translated, without a spreadsheet round-trip or a cloud account. This site documents all three, end to end.

The three tools

Each tool does one part of the job and hands off to the next. You can use any of them on their own — StringFlow Tables works with no server at all — but together they cover the whole path from a hardcoded string in a scene to a fully translated build.

StringFlow Tables

Finds hardcoded and unlinked text across your scenes and prefabs, and keeps your String Table Collections clean — duplicates, unused keys, coverage gaps.

StringFlow Translate

Fills in empty cells in a String Table using a local machine-translation server. Never overwrites an existing translation.

StringFlow Environment Setup

Installs and manages the translation server(s) StringFlow Translate talks to, running in Docker on your own machine.

Where StringFlow's data lives

WhatWhere
Your actual localized textUnity's own String Table Collection assets, exactly as the Localization package stores them — StringFlow never invents its own text format.
Backend list, routing rules, language-code mapsAssets/.../LibreTranslate/Data/TranslationEngineConfig.asset — a normal project asset, safe to commit.
Translation run history<project>/TranslationHistory/history.jsonl, next to Assets/ — plain-text log, one JSON line per run. Not a Unity asset, so it survives even a corrupted Library folder.
Docker containers & downloaded modelsDocker's own storage on your machine — nothing Unity-side, nothing in your project.

Where it runs

StringFlow Translate and StringFlow Environment Setup talk to a translation server running on your own computer, inside Docker. There is no cloud account, no API key, and no per-word billing — the trade-off is that the first setup downloads a few gigabytes of server and language-model files, once. StringFlow Tables needs no server at all; it only reads and edits your project.

Privacy

Nothing your project contains — table names, strings, translations — leaves your machine through StringFlow itself. The translation server is a process on your own computer, reached over localhost.

Before you read on

This site assumes you already have a Unity project with Unity's own Localization package (com.unity.localization) installed, and at least one String Table Collection with a couple of Locales. If you don't yet, the Getting Started page covers that first.
