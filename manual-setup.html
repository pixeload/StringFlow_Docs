Manual Setup (No Wizard)

Everything StringFlow Environment Setup automates, done by hand. Useful if the wizard is stuck on something environment-specific it can't see past, or if you just want to know exactly what's running on your machine and why.

You don't need this page for normal use

StringFlow Translate only cares that something answers at the URL configured in StringFlow Routing — it has no idea whether that server was started by the wizard or by you typing commands into a terminal. Either way works identically from StringFlow's side.

On this page

  • LibreTranslate, by hand

LibreTranslate, by hand

With Docker Desktop installed and running, in any terminal:

Pull the image

docker pull libretranslate/libretranslate

Run it

docker run -d --name libretranslate-service \
  --restart unless-stopped \
  -p 5000:5000 \
  -v lt-local:/home/libretranslate/.local \
  libretranslate/libretranslate

That's the whole thing. -p 5000:5000 publishes the server on http://localhost:5000; -v lt-local:/home/libretranslate/.local is a named Docker volume that keeps every downloaded language model on your machine, so a removed-and-recreated container doesn't re-download anything. On first start, the container downloads a translation model for every language it supports (~50 languages, ~20–30 minutes, a few GB) — that's normal; watch it with: 

docker logs -f libretranslate-service

Once it's ready:

curl http://localhost:5000/languages

should return a JSON array of language objects.

⚠ macOS: port 5000

If docker run fails to bind port 5000, macOS's AirPlay Receiver is almost certainly holding it. Either turn that off (System Settings ▸ General ▸ AirDrop & Handoff) or publish on a different host port, e.g. -p 5001:5000 — then point StringFlow at http://localhost:5001 instead (see below). Note the container's own internal port stays 5000 either way; only the number on the left of the colon changes.

NLLB, by hand

⚠ Read this first

NLLB's default model is released under a non-commercial licence. Read Licensing — NLLB before you build or use this one, manually or otherwise — building it yourself doesn't change what the licence permits.

NLLB isn't pulled from a public registry — its Dockerfile and Python service ship inside this package and are built locally. To do that build yourself instead of through the wizard:

  1. Gather the build files. In your project, find Assets/StringFlow/LibreTranslate/Environment/DockerSources/nllb/ — the exact path can vary depending on where StringFlow was imported in your project, so if that folder isn't there, use the Project window's search to find DockerSources instead. Copy these four files into a new empty folder on disk, renaming each as shown (Unity imports them with a .txt suffix so it doesn't try to compile them as code):
    In the projectRename to
    Dockerfile.txtDockerfile (CPU variant)
    Dockerfile.gpu.txtDockerfile.gpu (optional GPU variant)
    app.py.txtapp.py
    requirements.txt.txtrequirements.txt
  2. Build the image from that folder: 
    # CPU (works everywhere)
docker build -f Dockerfile -t nllb-translate-service .

# or, GPU (needs an NVIDIA GPU and Docker's --gpus support)
docker build -f Dockerfile.gpu -t nllb-translate-service-gpu .
  3. Run it, mounting a persistent cache directory so model weights survive a rebuild: 
    # CPU
docker run -d --name nllb-service \
  --restart unless-stopped \
  -p 5002:8000 \
  -v "$HOME/AppData/Local/UiToolKit/HuggingFaceCache:/root/.cache/huggingface" \
  nllb-translate-service

# GPU — adds --gpus all
docker run -d --name nllb-service \
  --restart unless-stopped \
  --gpus all \
  -p 5002:8000 \
  -v "$HOME/AppData/Local/UiToolKit/HuggingFaceCache:/root/.cache/huggingface" \
  nllb-translate-service-gpu

    On macOS/Linux, use whatever local cache directory you like in place of the Windows path above — it just needs to be a real folder on your machine, mounted the same way each time you run the container. The container listens on port 8000 internally; the example publishes it on host port 5002, matching StringFlow's default.

  4. Point it at a different model, if you want one. app.py reads the model to load from the MODEL_NAME environment variable, defaulting to facebook/nllb-200-distilled-600M. Add -e MODEL_NAME=your/model-id to the docker run command to use a different one — see Licensing for commercially-safe alternatives. 
curl http://localhost:5002/languages

should return the service's language list once the model has finished loading.

Pointing StringFlow at it

However a server was started, StringFlow only needs to know its URL. Open Tools ▸ StringFlow ▸ StringFlow Translate and press its Configure Routing… button to open StringFlow Routing, then set the backend's URL field to match whatever host port you actually published. Press Test — if it answers, the row goes green and StringFlow Translate can use it immediately, with no other configuration needed.

Since StringFlow always checks whether a server is already answering before doing anything else, opening StringFlow Environment Setup after starting a container by hand will correctly show it as Ready — including offering Stop / Restart for it, since it recognizes the container by name (or by the port it publishes, if you gave it a different name).

Stopping and removing

# Stop (keeps the container and its downloaded data)
docker stop libretranslate-service
docker stop nllb-service

# Remove the container (keeps the named volume / cache folder - nothing re-downloads)
docker rm libretranslate-service
docker rm nllb-service

# Remove everything, including downloaded language models
docker volume rm lt-local
# (for NLLB, just delete the HuggingFaceCache folder from step 3 above)
