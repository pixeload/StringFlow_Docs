Licensing & Third-Party Notices

StringFlow's own code is yours under the licence you bought it under. Everything on this page is about the third-party software it drives — none of which ships inside StringFlow itself.

The one thing worth understanding first

StringFlow ships its own C# code, a Dockerfile, and a small Python service. It does not ship LibreTranslate, Argos models, or NLLB weights. Each of those is downloaded by Docker or by the service container, from its own official source, onto your machine, at the moment you choose to install it. That distinction is why the licences below are things you agree to by using them — not terms StringFlow imposes on you.

LibreTranslate

LicenceGNU Affero General Public License v3.0 (AGPL-3.0)
Sourcegithub.com/LibreTranslate/LibreTranslate
How StringFlow gets itPulls the official public image libretranslate/libretranslate via Docker, unmodified.

AGPL is not a problem here because of how it's used: StringFlow talks to it over HTTP, as a separate process — it never links against LibreTranslate's code or redistributes it. If you were to modify LibreTranslate's own source and offer that modified version to others over a network, AGPL's terms would apply to that; simply running the unmodified official image to translate your own project doesn't trigger any obligation.

⚠ Non-commercial means the use, not just the download

CC-BY-NC-4.0 §2.1.1 grants the right to "reproduce and Share the Licensed Material ... for NonCommercial purposes only", and §1.9 defines NonCommercial as "not primarily intended for or directed towards commercial advantage or monetary compensation". The restriction attaches to running the model, not only to redistributing it — so using it to translate strings for a commercial game is a commercial use, even though the model itself never ships inside your build and isn't running at play time. Meta's own model card additionally states NLLB-200 is a research model "not released for production deployment".

Free availability isn't the same thing as permission — the download being free is exactly what the licence grants; the non-commercial clause is what it withholds.

For a commercial project, you have two real options:

  • Use LibreTranslate instead — fully permissive, no licence decision needed.
  • Point the NLLB service at a permissively licensed model. app.py reads the model to load from the MODEL_NAME environment variable, so this doesn't require rebuilding the image — see Manual Setup — NLLB for how to set it. Two options worth knowing:
    ModelLicenceLanguages
    facebook/m2m100_418MMIT100
    google/madlad400-3b-mtApache-2.0400+

    Note this is a genuine swap, not a drop-in: these models use a different tokenizer convention than NLLB (get_lang_id() with plain ISO codes, rather than NLLB's FLORES-200 forced_bos_token_id approach), so the service's translation call and its language map need matching changes, not just the environment variable.

Docker Desktop

Not included with StringFlow, and not installed by it — you install and run Docker yourself; StringFlow only detects whether it's present.

At the time of writing, Docker Desktop is free for personal use, education, non-commercial open source projects, and small businesses (fewer than 250 employees and less than $10 million in annual revenue). Larger organisations need a paid Docker subscription. Check Docker's current terms for your situation: docs.docker.com/subscription/desktop-license.

Alternatives that expose the same docker command line — Rancher Desktop, Podman, colima — generally work with StringFlow, since it only ever invokes docker and never anything Docker-Desktop-specific.

Unity Localization

StringFlow Translate and StringFlow Environment Setup require Unity's own Localization package (com.unity.localization), distributed by Unity under the Unity Companion License and not included with StringFlow. Install it via Window ▸ Package Manager ▸ Unity Registry. StringFlow Tables works without it.
